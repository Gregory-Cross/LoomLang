# Backing-read control for evaluator builds · PROPOSED

A build can return the right answer and keep a perfect account while secretly reading an operand it must leave untouched. For each build that claims a read discipline, run a separate instrumented copy on the same inputs. Watch where it actually consumes the operands. Pair a window that forbids reads with a live control for the same consumption route. Use a funded case when the page supplies one. The copy must still produce the sealed records byte for byte. OCaml is the first application. The same test applies to any host.

**Proposed installation path** — `docs/spec/evaluator/BACKING-READ-CONTROL.md`. This is a conformance procedure for the people checking a build. Keep its predictions and diagnostic results outside blind-reader packets.

A *payload* is the admitted content of a value. A *header* is separately validated metadata, such as its width. A *handle* names a value and a *slot* is an ordered operand position. A *backing read* is an operation that inspects the payload representation to obtain content or a property derived from it. Inspecting the backing array’s length to determine whether the value is zero counts even when there is no digit to load. Reading an already validated width from its header, copying a handle, and selecting an existing reference require no backing read. An *accessor* is a function through which the build claims reads pass. A *probe* independently observes backing reads. An *observer* selects the public facts a caller can obtain. Work held for a private computation becomes a debit only on commit.

## Obligation for a named build

For each claimed event kind, bind the governing page and descriptor, the offered starts, schedules and observers, and the particular build. Before running, derive a table from the page. For each **run, occurrence, visit, reached phase and ordered slot**, specify forbidden reads, permitted reads, and reads the rule requires. State any required index range, multiplicity, order, hold and origin. Distinguish a permitted choice of read order from a prescribed one. Identify the concrete unit the probe can see and the relation from that unit to the page’s unit. A stored word can supply several logical digits. A call to one function can consume several words or none.

For a window with observed reads B, every member of B must have a permitted phase, source slot and access under the bound rule. Check the observed sequence of access occurrences against the required counts, allowed maxima, order and extent for each slot and phase. A mapping may expand one packed load into the logical units it demonstrably covers. Distinct consumption occurrences required by the claim need distinct observations at that unit. Check each mapped occurrence once. Preserve any choice of order the rule permits. Unresolved attribution or multiplicity leaves the affected claim INCONCLUSIVE. An empty permitted set requires B to be empty across **all** operand sources. An empty observation discharges that test only with an observed window, complete coverage of its consumption routes, and a live positive control. If the build additionally claims that every read goes through its accessor, bind each consumption to the actual authorized call and hold for that event. An unlogged extra read in an otherwise funded phase can violate that claim too.

| Event or reached part | Required check for each observer named by the page |
|---|---|
| Pre-run admission or configuration refusal | Account for the scheduled offer and its admission report. Expect no reached event or event projection. Mark validation of incoming content in a distinct admission window when the page puts it there. An intentionally empty event selection cannot serve as the zero-read control. |
| Header-only quote and work check, including refusal | Start observation before operand lookup or width computation. Expect zero backing reads of either operand through the refusal, including calculation of width sets, deficits, witness creation and cleanup. A successful work check also requires zero in that initial phase. An earlier funded event in the same run can have legitimate reads. |
| Funded Add, truncated Sub or another row requiring payload-dependent sizing | Require the prescribed operand reads during the exact-size pass under the work hold. Include a construction refusal: sizing has occurred, emission has not, the hold releases and the debit is zero. On commit check any prescribed staging reads only under the full reservation. Derive their slot and extent from that operation’s page and concrete inputs. |
| Reference selection, constant-price binding, header bypass or padded operand | For the installed top-entry, literal and local rows, the quote and reference binding or selection consume no operand content. For admitted wrong-kind Add/Sub/Mul, both the work cut and the funded selection of the existing none consume none. Where a page skips a pass, fills a constant, or supplies a digit by header padding, require zero for that phase or absent slot/index. Other slots or later phases may still require reads. |
| Scheduled interruption, cleanup, projection or later event | Count only the permitted prefix actually reached. Require zero from every unreached operand-consuming phase and no read invented to complete a witness. Capture diagnostic reads through cleanup and identify subsequent projection or rendering separately. Grant a renderer its own read only when the applicable boundary permits it. |
| New event kind or observer | Instantiate the same table from its own page. A row that leaves an access optional yields a permission, not a minimum. An unspecified discipline leaves that part of the claim open. Do not infer a payload pass from affordability, a zero debit, an equal result, or the word “read” in the event name. |

Run ordinary and linked exact observations separately from fresh identical starts where both are specified. Check the private discipline on each run, even when ordinary buys no read evidence. Compare each output with its **own** sealed observation. Changing the public projection supplies no permission to inspect operand content. If a page explicitly gives an observer different access rights, bind that clause and test it separately.

## Place the probe where content is consumed

Identify all concrete consumers reachable from the claimed window, including helpers within the accessor implementation. Instrument value extraction, inspection of the backing length or tag, limb or byte loads, and any other route that can derive a property of the protected operand. Trace the actual consumption and return the original value. A reference lookup, a logged step or entry to an arithmetic helper is insufficient evidence by itself. Count representation operations separately by unit. For OCaml, review direct array accesses and generic operations such as comparison, hashing, conversion and serialization. For a host exposing value fields or eliminators, include direct field access and every route that can unpack the representation. Opaque native helpers need evidence at their actual boundary or a narrower claim.

Associate an admitted origin with each protected value or view after validation. Propagate that origin through aliases, borrowed views and copies. Carry the **source slot of this use** as context; the same reference may occupy both positions. Mark begin/end and phase transitions from the actual dispatch, hold and cleanup boundaries, independently of the result logger. Cover the interval after admission through event entry so prefetches or copies cannot move an unfunded read outside the brackets. Keep the diagnostic stream separate from canonical output. Record the build/run, start, observer, occurrence/visit, phase, reference/slot, kind of operation and index or bounded range where meaningful. Record unassigned reads and unmatched boundaries explicitly. Formatting the diagnostic itself must never inspect the payload.

**Shared zero is a coverage test.** Use an aliased zero, two handles to equal content where supported, and distinct nonzero operands. A shared empty array has a length but no limbs. Counting limb loads alone can therefore produce a false zero. An array address also cannot identify which logical operand was used. Observe the backing-length inspection with origin from the operand use, or use a tagged view that preserves the build’s actual sharing behavior. A forbidden read known only at event level already fails an all-zero window. If attribution is needed for a slot claim and unavailable, report the slot result INCONCLUSIVE and give its denominator. Do not silently pool such starts, remove them, or report their missing counts as zeros.

## Run and decision

1. **Bind the subject.** Record the measured build’s exact source, executable, host toolchain, dependencies, flags, commands and configuration. Bind the rule pages, starts, expected schedule and case-by-observer access table. Bind the measured build’s own sealed canonical stream for those inputs and observers and its independent correctness check. Enumerate selections and expected event windows. Choose a fixed bound for runs, events, reads and diagnostic size. A missing reference record or empty required selection leaves the gate open.
2. **Build beside it.** Make one fresh, isolated probe build from the same subject, with the same configuration apart from the recorded, reviewed instrumentation delta. Preserve the measured executable. Never ship or time the probe as that executable. Hash both executables and the delta. A reviewer checks that the edits observe the existing consumers, preserve their result, and leave the claim’s decision points and representations comparable.
3. **Exercise zero and liveness.** Run the sealed schedule serially. For each claimed path and observer, exercise applicable work cuts and genuine funded cases and establish liveness for the routes that the zero claims depend on. For the bake-off Add pair the same operands 5 and 3 give w=33. A01 at (32,3) requires zero through work refusal. A05 at (33,4) returned 8 and exercised both operands during sizing and staging in the reviewed OCaml build. Derive any minimum number of fresh backing reads for another build from the page and that build’s stated discipline. Check ordinary and exact separately. Include the selected Sub cuts and a funded Sub case for a Sub claim. For a zero-only row, use a funded sibling when it necessarily exercises the same representation and consumption route. If there is no lawful positive on that route, use a separately identified diagnostic calibration that exercises it with the relevant observer and phase attribution. Retain the genuine zero case. Confirm liveness for each applicable counter family, including length inspection of a shared zero. Keep calibration separate from the subject verdict. Missing route-specific liveness makes the associated zero result INCONCLUSIVE.
4. **Preserve origin and parity.** Acquire the shared build slot for native compilation and the required build/run slots for execution per the host rules. Release slots on every exit. Use one job sequence at a time, bounded checks under the 1 GB cap, and stream diagnostics. Compare the probe’s complete canonical stream byte for byte with the bound stream of the uninstrumented subject, including all private records, expected absences and purchased projections. Bind the capture to the measured executable, configuration, starts, schedule and observer. Independent reference comparison and decoding establish the correctness of that stream. Require the exact scheduled run identities and one complete bracket for every reached occurrence, including repeated visits. Check delivery from the observation point through collection, including the end of the run. For example, number observations before the side stream can drop them, reject gaps or duplicates and reconcile the received sequence with a checked final count from that observation point. An equivalent checked lossless path suffices. Reconcile attributed, unassigned and out-of-window reads. Any unresolved loss or read that could belong to a forbidden window leaves its zero claim INCONCLUSIVE. Keep the probe executable, invocation, stdout/record and side-stream hashes, exit status, limits and coverage counts bound to the verdict.
5. **Decide per claim.** PASS requires record parity, complete selections and brackets, a live positive control and satisfaction of every applicable access requirement. A forbidden observed read or a missing mandatory read with live, complete instrumentation is FAIL for that read claim. A canonical byte mismatch is FAIL for parity and precludes a read PASS. Retain any independently established access violation. A PASS also requires the probe to preserve access-relevant behavior of the measured subject at the claimed observation level. Unverified probe liveness, an unobservable route, a dropped diagnostic or unresolved attribution is INCONCLUSIVE for the affected claim. A reached resource or enumeration bound is CAPPED. State NOT RUN for an omitted selection or unexecuted build. Only PASS closes this gate for the bound build, pages, representation, configuration and exercised selections. Preserve any observed violation even when another part of the run is incomplete.

## Plan gate and cost

| Gate | Evidence entering the gate | Disposition |
|---|---|---|
| **Backing reads on a named, sealed subject** | The subject’s own record stream, independently derived access table, probe bindings, byte parity, phase and slot observations, zero and liveness controls, coverage and bounds. | Use the independent comparison and witness-decoding methods of rows 07 and 08 on the same subject. The witness reviewer independently checks the access table, instrumentation and observations and signs the read result for those bytes. In the slice-1 pilot, 07 and 08 gate the outside model from 06. Apply the standing control to 06 if it claims a read discipline. Check an actual evaluator build on its own bytes when it makes that claim. An open result holds the affected read claim. Recheck changes to subject or instrumentation before relying on them. |

P7 §6 estimates **about 0.5 agent-hour once to establish the control, then one extra build and one serial schedule run per version** of the measured subject, with all selected observers and controls in that run. This estimate assumes the measured subject already has a verified baseline for the complete selected schedule. Record setup and review effort, extra builds and runs, wall time, trace volume and limits. Budget separately for a missing baseline, newly selected cases, and any additional calibration build and run when a carrier or probe changes. The probe leaves the evaluator’s work and construction prices unchanged.

## What a passing probe leaves open

| Gap | Cheapest complementary check |
|---|---|
| An unused or uninstrumented path bypasses the accessor, or an entire counter family is silent. | Inspect direct consumers of the carrier, including generic/foreign operations and generated code where relevant. On setup and after a relevant carrier or probe change, use a separate calibration variant with a known direct consumption in a forbidden window, outside the public accessor. Establish that the consumption executes at the claimed observation level, its value is discarded and canonical bytes still match the clean baseline. Require zero forbidden observations in the clean control and a failure for the injected operation in the variant’s specified window. Decide the clean PASS only once calibration and the other checks succeed. Attribute it at the granularity required by the claim. A build error, byte mismatch, unrelated rejection or eliminated injection does not validate the detector. Keep this expected failure separate from the clean subject’s result. |
| A total hides reads of the wrong operand, reads after release, or a later event charged to the first. | Check per-slot phase intervals against hold/release markers and run the smallest alias, reversed-slot, repeated-visit and interrupted-prefix controls that exercise the ambiguous path. |
| Instrumentation changes access behavior or the optimizer removes or introduces a route. | Compare the instrumentation delta and actual call paths around the decisive branch. Inspect emitted code there if source inspection cannot establish comparability. Canonical byte parity alone cannot settle this question. |
| The tested starts miss a width, representation or schedule, or a value is already copied before the event. | Add the nearest boundary pair and a multi-limb or zero example. Trace creation of the protected view from validated admission through the first quote. Record the remaining unexercised cases. |
| Content is read lawfully but the price, value, record, or public projection is wrong. | Use the independent price/record comparison and witness decoder for the same subject, following the methods of 07 and 08. The read probe adds an independent observation to those checks. |
| The claim concerns CPU memory traffic, timing, speculative access or all workloads. | Limit the verdict to the stated source-level consumption units and selected starts. A machine-level claim needs its own scoped machine-level observation; this run supplies no such measurement. |

## Basis for the proposed control

**SOURCE.** P4-RULINGS §2 distinguishes two OCaml measurement units. The probe that registered backing arrays by physical identity reported touches on 42 of 44 planted work refusals. It could not attribute the two S05 observer runs over the shared empty zero. Counting underlying length inspections as well as limb loads detected a read on all 44, with 88 length inspections and 80 limb loads. Those totals count different operations. The two Lean reviewers used value/digit consumption and field-access probes; their handoffs identify the scope of the observation and routes needing source review. All four recorded genuine refusal silence and live funded controls. Admission-time validation was separately ruled outside the bake-off event window. These are reported experiments on the bake-off subjects.

**SOURCE.** DESIGN §15.12 distinguishes validated metadata, held sizing and commit. The evaluator spec plan’s Add producer/comparison/decoder and the slice-1 event plan’s rows 06–08 distinguish an outside model from the actual producer. The installed Add, Sub, Mul, wrong-kind and entry/read pages supply the examples above under their named descriptors. The owner approved the OCaml increment and this standing-control follow-up. The control’s wording, installation path and gate placement here are PROPOSED; no build was probed in drafting it.
