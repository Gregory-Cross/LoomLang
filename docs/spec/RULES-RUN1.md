## RUN1-001 — Reference state and order of execution

- revision: 1
- standing: DRAFT transcription; the source standings below are retained, including the shapes' unfulfilled slice-1 test condition.
- kind: definition and requirements
- subject: the reference program step, its abstract state and the ordering, binding and reuse obligations that govern its execution
- from: SOURCE R12:565–582 (D-RUN-1–6); R12:584–589 (D-RUN-7 state); R12:597 (D-RUN-8 function value/counting/no result table); supporting R12:134,138 (D-UO-6/8),242 (D-OP-2),1014 (D-ATT-1)
- prerequisite: INFERENCE Checked terms, signatures, rule patterns, environments and admitted values are supplied premises, as required by the source's admission interfaces. Their existence here does not establish the full operational ADM gate. Runtime state, value, frame, handler and activation representations remain RG-001/RG-002.

- text S1: SOURCE The reference run is a program for the evaluator called step. Operation arguments run before the operation, left to right. A symbol's rules are tried in written order; the first matching rule is applied. Patterns consist of constructors and variables, each variable once. At an operation with a continuation, step stops and asks. R12:571 is **agreed, not run**. It calls for compiled/reference agreement and generated-input checks in each slice; this draft performs neither.

SOURCE — If no rule matches the obtained argument values, the call fails with the symbol and its arguments at observed sorts as its payload; an argument of a use-once sort is not in that payload and remains held (D-PATH-3, R13:699). INFERENCE — Trying and rejecting a pattern is not by itself permission to consume or drop an obtained argument; subsequent patterns must be tried against the same obtained values with their obligations intact. Where no selected interpretation answers the failure, report failed(payload, held) under O1. This does not add literal patterns or settle the separately open handler implementation. The executable matcher and its preservation evidence remain RG-001 work.

- text S2: SOURCE The state is the following abstract account, with the exact D-RUN-7 fields and alternatives. R12:584 is **approved, as forced move 19**, with **shapes to be tested by building slice 1**; that an outcome names what is held was approved earlier. A function value holds its body and its environment, the reference counts consumption per use-once value, and D-RUN-3 requires no table of results (R12:597, **approved, as forced move 19**). This state sketch chooses no memory layout, serialization or transition tariff.

```
state = { control: a node with its environment, or a value;
          frames: what remains to be done;
          handlers: the handler frames in force;
          next activation: a count;
          fuel: what is left;
          consumed: a count for each use-once value }
```

INFERENCE — Sequence-bearing runs need a bound account of reachable sequence contents, fresh sequence identity, and the changes made by the run, in addition to the D-RUN-7 sketch. D-SEQ-1 (R13:988) says a change is a fact even when nothing later reads it. The six fields above do not by themselves supply that account. D-SEQ-2/3 (R13:990/992) retain their separate decided and proposed standings; this paragraph selects no new state field, store layout, counter construction or record bytes. The sequence contract supplies the state and identity obligations, and RUN1-001/003 must bind their checking to the run and comparison. The compared runs must start from matched sequence state under that relation; equal sequence identities alone do not establish matching initial contents. For a run that can make or change sequences, a match of requests, ordinary outcome and use-once consumption alone does not establish agreement. The applicable sequence obligations must also be checked under the tracking relation; otherwise record that work as unchecked and the comparison as incomplete, unless an irreversible checked violation already establishes mismatch. Equal final contents alone do not establish that the same changes happened. RG-001 and RG-008 retain this explicit sequence dependency.

- text S3: SOURCE An operation with a continuation runs where its term puts it. Exchanging, sharing or dropping two such operations requires the claim about them at their selected interpretations; distinct row symbols grant no exchange. Laws, tools and models in a row impose no order. A possibly nonterminating term is not dropped or run early without evidence that it terminates. D-OP-2's set-of-outcomes reading applies only to picks unresolved on both sides and under its independence, continuation and scope conditions; other exchanges need the stated claim about selected interpretations, scope and observations. These are the **agreed/approved** order constraints in R12:565–569; they do not make every open-choice move permissible. D-OP-2's approved condition at R12:242 remains **to be tested**.

- text S4: SOURCE An argument runs on each activation of the operation holding it; a variable denotes the already obtained value in its binder's activation and runs nothing again. Bind a run where it is to be shared. Separately, a completed result may be reused at the same values of its variables only under all five stated conditions: the term makes nothing new, has no effect, has no open choice, consumes nothing use-once, and has a copyable result. Making a sequence or a use-once value makes something new. Consumption is a property of the run, not an absence of free variables: read(K()) can consume while closed. This completed-result permission needs no separate evidence that the term ends, but never skips, drops or runs early an unfinished computation. Node equality alone grants no reuse. SOURCE — D-RUN-3 permits completed reuse only where it cannot be seen (R13:574). INFERENCE — Equal variable values, including the unchanged identity of a mutable sequence, do not by themselves establish that a result which depends on sequence contents is still valid. Before reusing such a result, establish that the relevant state still supports that result under the applicable observations; without that evidence this permission does not authorize the reuse. This states no blanket permission for contents to be treated as effect-free, chooses no invalidation algorithm, and does not make the proposed D-SEQ-3 state-free test a new sufficient or necessary test for every reuse. SOURCE — R12:573 retains **working: C22; the R29 copying/consuming words approved**, plus the **owner-recorded OQ1 A with Arch's condition** qualification; R12:574 is historical fixture evidence only.

- text S5: SOURCE A writer seeking one run names it; a rule step copies an obtained value only where its sort permits and binds an unrun term before placing it twice. Code-level sort membership by same, identity laws, caches and claims remain about nodes (R12:576, **working: C22**, plus the **owner-recorded OQ1** qualification). D-ATT-1 supplies the fresh-production restriction on identity reasoning. **PROPOSED, not owner-decided:** extending the full result-reuse condition to laws is the separate proposal in R12:576/1014; its necessity and scope remain RG-014. On a variable-bearing term, applying a rule also requires that no earlier rule could match an instance (R12:578, explicitly **author's**). This latter qualification is not silently promoted to approved status.

- text S6: SOURCE D-RUN-6's planner permission requires no row effect, no open choice, no possible nontermination and no use-once consumption. Running again at a second place is a move of the same kind. Fresh-producing work is neither shared nor rerun. Every reference run producing a use-once result must have its corresponding fresh production, even if the result appears unused. Elision of an unread fresh sequence remains **OPEN** because it changes later sequence naming and awaits the matching relation (RG-013). Moves/sharing retain argument bindings, activation and whether each claim was admitted by evidence, a guard or a named assumption. Evidence that justifies the move, or that lets a guard be left out, must be reread and yes at the destination. A named assumption stays an assumption, with its lock place; it does not turn into yes. A passed guard supplies yes only for the same values, in a state it still describes, and where it precedes the use on every path. Otherwise the use needs other evidence yes there or its own guard. Rule 10 continues to apply. Completed-result reuse under S4 is separate. R12:581 retains its **approved** tag and **owner-recorded OQ1** qualification; neither closes its explicit unread-sequence gap.

- deciding case: PROPOSED C01 — Track pair(work(), work()) as two evaluations under the definition, or permit completed-result reuse only when all five S4 conditions and equal variable values are established. Pair(K(), K()) for fresh use-once producer K must retain distinct productions. C02 — With f(zero)=one before f(n)=two, rewriting f(x) to two before knowing x violates the source's author's first-match restriction when applied to zero (R12:579). C03 — Hoisting exact division above the guard establishing a nonzero divisor loses the site-specific evidence even if the row looks effect-free (R12:582). C04 — Preserve live handler frames and the binder activation through a call; looking up a bound value does not invoke its producer again. These discriminate the transcribed constraints; all are NOT RUN and supply no transition implementation.
- excludes: SOURCE / INFERENCE No equality of nodes or content as a fresh-production identity; no four-condition or state-free-only reuse licence; no inference from lexical indices to valid runtime environments; no result table required by this state; no new core-let encoding or general applied-binder exception; no selected unread-sequence elision or general extension of reuse conditions to laws; no termination, optimizer or lowering proof.
- gaps: RG-001, RG-002, RG-005, RG-007, RG-013, RG-014
