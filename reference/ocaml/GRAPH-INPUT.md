# Resolved graph input for increment 1

SOURCE · A graph is a unary definition represented by an ordered list of nodes and the index of its body. A node index identifies an occurrence. A parameter position identifies its binding. A handle is a key in the start's finite map from keys to admitted naturals. A descriptor selects a finite set of price rows by the SHA-256 digest of its exact bytes. The entry event is implicit in applying the definition to an admitted input.

These fixtures use JSON arrays as graph data. The outer array contains the string `unary-natural`, the node array and the zero-based body index. A local node is the pair `["local",1]`, referring to the sole parameter by its one-based position. A literal pairs `"literal"` with canonical decimal digits for a natural. An Add node contains `"add"` followed by the two earlier node indices in operand order. The submitted graphs are trees. The node array is in left-to-right postorder, with the body last. Entry and local binding never look up a display name.

The canonical graph bytes are UTF-8, with no BOM or whitespace between tokens and exactly one final LF. Decimal naturals have no redundant leading zeros. Node and parameter indices are JSON integers. SHA-256 covers the whole file, including its final LF. A start binds the expected graph digest separately from the offered graph path. Admission checks the offered bytes against that binding and checks the graph before entering the root. The fresh off-schedule control offers a well-formed graph with literal 4 against the schedule for literal 3. Its expected outcome is a pre-entry refusal with no event or event projection.

The graph fixture runner verifies the descriptor file against the start table's digest and finds the scheduled graph bytes by their digest independently of the offered path. Its command passes the scheduled and offered digests at arguments 4 and 5, and the hexadecimal encodings of the scheduled and offered bytes at 11 and 12. This runner owns the digest-to-bytes check. The evaluator compares the two byte strings, decodes the offered graph and requires the selected descriptor to cover entry and every node before running entry. The Add descriptor supplies Entry, Local, Literal and Add. The Sub descriptor supplies these four rows and Sub. An unknown descriptor or a missing row refuses the graph before any event or projection.

Each graph start supplies its offered `input_handle` separately from its admission map. In the original A0 fixtures that map has the single key `i1` and value `admitted_natural`. A start can set `admission_handle` to name a different key for the same one-entry map. The command passes the natural at argument 7, the offered key at 14 and the admission key at 15. An empty key represents absence. Only a nonempty offered key equal to the admission key binds the natural. Entry and local-origin witnesses carry the admitted key. A missing binding yields an empty input reference (JSON null) in the start header and a pre-entry refusal when graph and descriptor admission succeed.

The starts file selects the two observers separately for each graph and grant. Both equal-value starts admit input 5, allowing the two origins to be distinguished even when interning yields the same value reference. The carry start supplies 7 to a graph with literal 1.

The Sub edition additionally admits the binary node `"sub"` with the same two resolved child indices. Graph argument 13 supplies the actual limiting scope. The runner uses the optional start field `scope`, defaulting to `serial-root` for the Add table and `root` for the Sub table. A graph that uses Sub requires `root`, which also labels its bound expression on a work refusal.

An obtained schedule is an ordered, nonempty sequence of prepared Add or Sub occurrences with distinct site names. Selection names one site and its sole visit is numbered 1. Admission checks the whole sequence before the first event, including sites and rows in a suffix that an earlier cut could make unreachable. The first operation determines the limiting scope, `root` for Sub and `serial-root` for Add. Every Sub in the sequence requires `root`.

The obtained start may set `selected` to a site name. Its default is the last site. The runner passes that name at argument 11. After checking distinct sites, descriptor rows and scope, admission checks that the selected site occurs in the schedule. An absent site gives the pre-entry refusal `unknown selected occurrence`. Admission then checks the intervention at every site, including the suffix following a potential cut. The event field `interrupt` takes a JSON boolean. The runner encodes false as `none`, true as `interrupt` and any other JSON value as `unsupported`. Add and Sub accept `none`. Only Add accepts `interrupt`, which requests an interruption after staging and before commit. Any other combination gives the pre-entry refusal `unsupported intervention`.

Both observers report the return or stop of the whole schedule. The exact observer also reports the selected occurrence's debit, its balance after commit or cleanup, and its purchased supplementary fields. A later event can change the final result and account balance. The selected readings still refer to the same occurrence. When an earlier stop prevents a valid selected site from being reached, the exact observer reports zero debit, the balance after cleanup, and no supplementary fields.

For a paid Entry, Local or Literal, the committed entry retains the value together with a witness whose return field holds the checked natural's immutable identity (`Json.Num_ref`). Preparing that field retains the identity as a reference. After publication the witness serializer reads its decimal digits and emits the return as a JSON number. The same rendering applies to a successful final projection.
